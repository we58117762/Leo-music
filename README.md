## 我们如何使用

以下为简明原则，具体职责和交付细则以[协作流程与交付规范](协作流程与交付规范.md)为准。

1. **先讨论，再动手。** 从原曲的特点、歌词、情感和演唱者出发，寻找这首歌自己的处理方式。
2. **把好听的原因说清楚。** 不只记录 Style，还记录前奏、间奏、尾奏、各段唱腔和情绪变化的设计。
3. **试听之后再记录结论。** 区分「设计意图」「用户听后确认的效果」与「还需实验的猜想」。
4. **跨歌曲复用审美经验，不复制编曲配方。** 不强制高音、强混、大鼓、特定乐器或统一参数。
5. **增量维护。** 新发现更新共识，新歌增加案例；保留旧结论和重要修订线索。

## 文件与版权

**每首歌的第一核心资产是最终实际使用的完整 Suno Lyrics**（原词、段落标签、唱腔、乐器与情绪指令）；同时保存 Style、Exclude、参数、试听反馈与必要的旧版本，确保可以回看和重新试验。对历史作品，若当次粘贴稿已不可核实，明确标注「整理重建版」，不冒充原样备份。

用户提供的原始 LRC、旧版制作文档及来源信息，可以与案例一起保存作私人研究与版本对比。加工原词不会自动取得歌词版权；本仓库维持私人用途，不把受版权保护的整首歌词或原曲音频公开发布。
